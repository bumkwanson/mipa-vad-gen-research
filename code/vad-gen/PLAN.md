# vad-gen 프로젝트 계획

> Video Audio Description generation — 비언어 신호 기반 영상 화면해설 생성 시스템
> (프로젝트명 미정, 임시로 vad-gen 사용)

## 1. 목표 (한 문장)

한 명이 등장하는 짧은 영상에서, 대사(자막)만으로는 놓치는 표정·제스처·침묵 같은
비언어 신호를 함께 해석해서, 시각장애인 화면해설(Audio Description)에 가까운
장면 설명을 자동 생성하는 시스템.

## 2. 배경 / 문제의식

- 기존 영상 자막·요약(유튜브 자동자막 등)은 대사(음성)와 화면 텍스트(OCR) 중심.
- 인물의 표정, 제스처, 침묵 같은 **비언어 신호를 언어화하지 못함**.
- 특히 시각장애인용 화면해설에서 이런 비언어 정보가 중요한데, 자동 생성이 약함.
- → 비언어 신호를 풍부하게 서술해 화면해설 품질을 높이는 것이 목표.

## 3. 범위 (KCI 기준, 작게 확실하게)

- 등장인물 **한 명**, 짧은 클립(10~30초).
- 영상은 **외국(영어) 영상**, 최종 출력도 **전부 영어**.
- novelty 방향: **비언어 신호를 풍부하게 서술** (화면해설 품질 중심).
  - 언어-비언어 불일치(incongruence)는 이번엔 메인 아님 → 향후 연구로만 언급.
- 목표 결과물: SRT 자막 파일 + 자막 입힌 데모 영상.

## 4. 파이프라인

```
영상 클립 (한 사람, 영어)
   │
   ├─ [영상] 프레임별 분석
   │     ├─ POSTER++      : 표정 인식        (완성)
   │     └─ MediaPipe     : 제스처 해석       (신규, 규칙 기반)
   │
   ├─ [오디오]
   │     ├─ silero-VAD    : 발화/침묵 구간    (완성)
   │     └─ faster-whisper: 대사 + 타임스탬프  (완성, 영어 STT)
   │
   ├─ [시간 축 정렬]  구간별로 표정·제스처·대사·침묵 묶기   (신규)
   │
   ├─ [LLM] 화면해설 서술 생성                              (신규 프롬프트)
   │     - EXAONE 영어 성능 테스트 → 부족하면 영어 강한 모델로 교체 검토
   │
   └─ [출력]
         ├─ SRT 자막 파일 (타임스탬프 + 대사/화면묘사)
         └─ ffmpeg 자막 입힌 데모 영상 (.mp4)
```

## 5. 모듈 상태

### 재활용 (검증 완료)
- POSTER++ 표정 인식 (vad-gen/src/vision/poster_infer.py)
- faster-whisper STT (영어)
- silero-VAD (soundfile로 오디오 로드, torchaudio 우회)
- LLM 연동은 Ollama HTTP API 방식 (transformers 직접 로드 문제 회피)

### 신규
1. 제스처 해석 모듈 (MediaPipe 랜드마크 → 의미 해석, 규칙 기반)
   - 손이 얼굴/입 근처 (긴장, 생각, 손톱 물기)
   - 손이 목/뒷목 근처 (머쓱함, 난처함)
   - 고개 숙임/돌림 (시선 회피)
2. 영상용 통합 파이프라인 (실시간 루프 → 파일 배치 처리)
3. 시간 축 정렬 (발화/침묵 구간 × 표정/제스처/대사)
4. 화면해설 프롬프트 (영어 서술체, 화면해설 관례 반영)
5. SRT 자막 출력
6. ffmpeg 데모 영상 (자막 입히기, 폰트 지정)

## 6. 작업 순서

1. [ ] 제스처 해석 모듈
2. [ ] 영상용 통합 파이프라인 (표정+제스처, STT+VAD를 시간축에 정렬)
3. [ ] 시간 축 정렬 + 화면해설 프롬프트 설계 + LLM 연동
4. [ ] SRT 자막 출력
5. [ ] ffmpeg 자막 입힌 데모 영상
6. [ ] 테스트 클립으로 end-to-end
7. [ ] 정성 평가 + 논문 정리

## 7. 논문 구조 (KCI 5장, 투고 양식 기준)

1. 서론 — 문제 제기(자막은 비언어 놓침, 화면해설 한계), 기여도 나열, 논문 구성
2. 관련 연구 — 화면해설(AD), 영상 요약, 감정/표정 인식, 제스처 인식
3. 제안 시스템 — 파이프라인 상세
4. 구현 및 평가 — 사용 모델, 제스처 규칙, 클립별 결과, 정성 비교
5. 결론 및 향후 연구 — 다중 인물, 불일치 감지 확장

### 양식 필수 요소 (투고 양식에서 확인)
- 한글 제목 + 영문 제목
- 국문 요약(7줄+) + 영문 Abstract(7~8줄)
- Keywords: 영문, 4~6개
- 참고문헌: 8개 이상 (2개는 국제논문), 본문 등장 순서
- 그림/표 안은 영문 표기만

## 8. 환경 메모 (재현 시 주의)

- venv: ~/mipa/poster_plus_plus/venv_poster 재사용 (vad-gen/venv 심볼릭 링크)
- torch 2.11.0+cu128 (RTX 5060 Ti Blackwell, cu128 wheel 필수)
- mediapipe==0.10.21 (최신은 solutions API 제거됨, 다운그레이드 필요)
- transformers==5.1.0 (EXAONE 커스텀 코드 호환 버전)
- timm 0.3.2 → torch._six shim 필요
- POSTER++ → RecorderMeter 더미 클래스, weights_only=False 필요
- silero-VAD → soundfile로 오디오 로드 (torchaudio 2.9+ torchcodec 이슈 우회)
- LLM → Ollama (transformers 직접 로드 시 VRAM 피크로 OOM)

## 9. 열린 질문 / 나중에 결정

- 프로젝트 최종 이름
- LLM: EXAONE 영어 성능 확인 후 유지 vs 교체 (llama3.1, qwen2.5 등)
- 테스트 클립: 저작권 문제로 CC 라이선스 or 직접 촬영 필요
- 대사와 화면묘사가 겹칠 때 자막 표시 방식
